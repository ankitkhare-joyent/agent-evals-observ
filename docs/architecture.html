Agent evals and observability: the whole system

Everything built in agent-evals-observ, around the unchanged EC2-inventory agent from learn-ai-agent. Numbers in circles match the walkthrough below.

agent requests telemetry (OTLP) evaluation (datasets, scores, judging) secrets delivery

Walkthrough

  1. Instrumentation. In the same Python process as the agent, observ/genai.py patches the Anthropic SDK and the MCP client. Every run becomes a trace: invoke_agent at the root, a chat span per model request (model, tokens, cache hits, cost), a tools/call span per MCP tool call (arguments, result, errors). Trace context also travels inside MCP's params._meta.
  2. Offline evals. The runner asks the MCP tools for today's facts, builds golden cases, runs the agent's real entry point k times per case, rebuilds each trajectory from its spans, grades it with code and an LLM judge, writes reports and fails CI if a gate is missed.
  3. Online evals. A scheduled job samples real traces from Langfuse, judges them without a reference, and writes scores back. Low scores become new golden cases.
  4. Collector. The only thing apps talk to. It drops nothing under pressure, masks secrets, caps sizes, derives exact RED metrics for Prometheus, tail-samples, and forwards to Langfuse with a key it got from OpenBao.
  5. Langfuse. Stores traces in ClickHouse via an S3 event log and a Redis queue, links eval traces to the dataset as experiments, and holds every score.
  6. OpenBao. Holds every secret. Sidecars log in with their own AppRole and render secrets into memory-only volumes; the eval runner logs in itself. Nothing secret is in compose, config or git. The agent's own credentials stay in the lakehouse's OpenBao.
